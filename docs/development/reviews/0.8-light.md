## 3. Findings at 75 or more

**L1. The guide's row for `stream: cannot connect: error N` misses the cause the release adds** (score 75)
- dimension: Documentation
- file / line: `docs/user-guide.md:616`, and the troubleshooting entry `:689-691`
- evidence: `:616` "`stream: cannot connect: error N` | the server's stream port cannot be reached: 9000 by default
  with LMS, 8097 with Music Assistant"; `CHANGELOG.md:47-49` "A TCP/IP stack that refuses to make a connection
  non-blocking is now reported: `socket: error N`, then a retry, or `stream: cannot connect: error N` for a track.";
  `stream.c:151-154` prints it for any `plat_connect_start()` below 0, now also when the socket cannot be made
  non-blocking. The row for `socket: error N` (`:602`) was updated, this one was not.
- failure scenario: a TCP/IP stack refuses non-blocking mode on a stream socket; the user sees `stream: cannot
  connect: error N`, and the guide sends them to a blocked port 9000 or 8097, or to Music Assistant's published
  address, to check in vain.
- rule: `CLAUDE.md:21` (each user-visible change: the user guide updated); the method: a message described wrongly
  in the user guide is 75.
- proven or inferred: proven (read in the code, the guide and the CHANGELOG).
- suggestion: add "or the TCP/IP stack refuses to make the connection non-blocking" to `:616`, as in `:602`.
- what would lower it to 50: a stack that refuses non-blocking mode refuses it on the control connection first,
  which gives `socket: error N` before any stream; only a stack that refuses it some of the time reaches this row.
- found by: review-tests-docs (75).
- seen before: new (the cause came with `25c935d`, in this range).

## 5. The 50 list

- `stream.c:138-139`: when the track queue is full, the forgotten track is decoded by the previous track's
  decoder: a crafted unit test played a WAV header as sound, the elapsed time running on through it. The rewritten
  comment says "one STMs fewer" and gives a size trigger, not the server behaviour that makes it unreachable. 75
  if a server is shown to stream more than one track ahead. Seen before (0.8 `:258`, the comment), the consequence
  new.
- The refusal of a non-blocking socket has no test on either platform: the guard removed, `make test` stays green
  (as `25c935d` says). New.
- `show_ascii`'s upper bound (`slimproto.c:204`, `<= '~'`): widened to 0x7F, the tests stay green. New.
- `slimproto.c:194-195` "as the player name from setd" and `CHANGELOG.md:50-51` "a byte outside it shows as `?`":
  CR is dropped and LF kept in the request, both shown as `?` in the name. New.
- `test_core.c:621`: `test_stream_sequence`'s comment now sits above `test_strm_request_shown`. New.
- `PLAYER_FAIL` for a server not found (`player.c:387`) and for `ahi.device` (`player.c:403`) is checked by no
  test; R2's window depends on it. New.
- The plan's player-17 lists a test for "a stream that cannot be opened", which `test_core.c:2298` leaves out, and
  "a MAXRATE too large refused" under code, unchanged since player-13 (`86f772c`). Internal. New.
- `amiga.c:60-62` still says "dr_flac about 5 KB, minimp3 about 17 KB", fixed in the `Makefile` only. New.
- `amisqueeze.fpu`'s stack last measured in 0.7 (WinUAE, `bsdsocket_emu`), never with discovery or a real
  `bsdsocket.library`; margin about 15 KB. New.
- `quiet_hold` starts again at 0 when a message does not fit: older messages may go while there is room for part
  of them; the failing one is always shown. New.
- No script checks the rule against `printf` in the core: `check-core.py` accepts `<stdio.h>` (A5); nor an
  `#include MACRO` or a hand-written prototype. New.
- `user-guide.md:670` "said once per connection" for the `stream:` line, said once per stream. Seen before (0.8
  `:250`, as unguarded), before this range.
- `slim_discover` says "8 servers answered" when nine answer; `test_discovery_nine` keeps that wording. Before 0.8.
- `player.h:208` `player_bench` "returns PLAYER_OK", while `player.c:193-198` can return `PLAYER_FAIL`; harmless.
  Before 0.8.

## 6. Checked and found solid

- Every new unit test catches the guard it was written for: 19 guards removed by review-tests-docs, all red at the
  expected lines, confirming the records of `2feb2cb`, `597efef`, `e51f74e`, `9f701d7`, `616ba9f`, `d123926`,
  `c65fa52`, `86f772c`, `63d2017`; review-protocol-security found the same for its four.
- `send_failed`: set only in `send_all`, reset only in `slim_connect` before the HELO; every send returns early on
  a closed socket; a failure is caught in the same turn or the next, after one `plat_wait`.
- `show_ascii`: reads `b[0..len)` with `len >= 28` guaranteed by `process_strm`; its buffer flushed at 64 (the flush
  removed: UBSan red).
- `make_nonblocking` on both platforms saves the error before closing the socket and returns -1; the callers do not
  close it again.
- `wb_quiet`: 1 to 0 when a window opens, 1 to 2 to 0 after `player_main`: no window opened twice, none left open;
  every `PLAYER_FAIL` of `player_main` comes before `run()` and prints its message first.
- The new safety nets run in the CI: `check-core.py` through `make test` (host job), `check-stack.py` and
  `--check-text` through the `amiga` job.
- No linked code changed since the A1200 stack measurement (`ae71a6e`): it stands.
