## 3. Findings at 75 or more

**L1. The Xircom limit says the guide's CPU figures come from a fixed driver, right after two figures measured with
Aminet's** (score 75, proven)
- dimension: Documentation
- file / line: `docs/user-guide.md:852-860` (Known limits); against `docs/development/performance.md:146-147` and
  `:168-169`
- evidence: `user-guide.md:854-858`: "AHI's Paula driver 4.33 ... with `AHIpaulaBufferLength` at 2048: about 86 % of
  the CPU" and "AmiNetXDuo's `RXBUFFER=8192` ...: about 90 % of the CPU", then `:860`: "The CPU figures of this guide
  were measured with a fixed version of that driver, not published." `performance.md:168-169`: "With Aminet's build
  of 1.1, 4.33: ... 86 % and no crackle at 2048 (`RXBUFFER=8192` instead: 92 %, above)"; its table, `:147`:
  "Aminet's 1.1 | 8192 | 92 %".
- failure scenario: a user with Aminet's `xircomce2.device` 1.1, the only one published, reads 86 % and 90 %, then
  that the guide's figures come from a fixed driver: they expect a higher load than 86 % with the 4.33 route, or
  apply the sentence to the wrong figures. The 90 % also rounds the 92 % measured.
- rule: the method's scoring (a statement of the user documentation proven false); `documentation-rules.md`,
  History (a measure names the build it was made on); A2
- proven or inferred: proven (read in both documents). The sentence and the 90 % predate the range, which added the
  86 % and rewrote the bullet around them.
- suggestion: say in the bullet that both figures are with Aminet's 1.1, give 92 % as `performance.md` does, and
  restrict the sentence to the guide's other figures (the Slow row).

**L2. The archives' link check and rewrite skip a Markdown link with a title** (score 75, proven)
- dimension: Code
- file / line: `tools/make-dist.py:57` (`INLINE_LINK`); claims at `tools/make-dist.py:12-14` and
  `docs/development/building.md:115-117`
- evidence: `INLINE_LINK = re.compile(r"\]\(([^)\s]+)\)")` cannot match `[x](target "title")`. `building.md:116-117`:
  "A link to no file is refused; `make test` checks the links too."
- failure scenario: planted by `review-platform` in `docs/user-guide.md`: `[titled](missing-titled.md "a title")`.
  `make-dist.py --check-text` reported the plain and angle-bracket plants and said nothing about this one. A
  contributor who writes `[README](../README.md "x")` in the user guide ships an archive whose link leads nowhere
  (the archive is flat), with `make test` green: R6's defect back, silently. No titled link exists in the repository
  at the commit.
- rule: A4 (a safety net that does not catch its class), A2 (`building.md`, a page of the rules, proven false)
- proven or inferred: proven (planted defect, `make test` output)
- suggestion: accept an optional title in the pattern (`\]\(([^)\s]+)(?:\s+"[^"]*")?\)`) and keep it when
  rewriting; or refuse any `](` the pattern does not parse.
