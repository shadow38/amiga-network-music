## 3. Findings at 75 or more

**R1. Paula direct overruns its chip RAM buffers on the first block of a mono FLAC or MP3 track at a rate Paula
does not divide** (score 75, proven on the host; the Amiga corruption to confirm)
- dimension: Code / Security
- file / line: `src/amisqueeze/output.c:206` (block sized) before `:212` (decoder run); `slimproto.c:239-243` (the
  guess); `audio.c:354-367` (`audio_block_room`), `:217-220` (`convert_paula`); `platform.h:110`
  (`PAULA_BLOCK_SAMPLES` 8192); `amiga_paula.c:195` (buffers back to back); comments `output.c:180`,
  `player.h:409-411`
- evidence: `slimproto.c:239` `if (pkt[6] == 'f' || pkt[6] == 'm') { /* a guess until the decoder reads the
  stream's header */ f->rate = 44100; f->channels = 2;`; `output.c:206` `full = audio_block_room(p,
  &t->out_fmt);` (PAL 44100: divisor 2, room 32768 bytes) then `:212` `n = o->dec.ops->run(..., full);` and
  `:213` `t->out_fmt = o->dec.out; /* known once the decoder has read the stream's header */`. `flac.c:271-273`
  sets the real format in its OPEN phase and goes on decoding in the same call; `mp3.c:218-223` likewise. 32768
  bytes of mono 22.05 kHz = 16384 frames, divisor 1: `convert_paula` writes 16384 samples per channel into 8192-byte
  buffers. Host proof (review-protocol-security, a test in its worktree): `m16-l5.flac` with its STREAMINFO rate set
  to 22050, `AUDIO_PAULA`, PAL: "first sends: max start+len 16384 (buffer 8192), stub_paula_bad 1"; the same file at
  44100, and a 22.05 kHz stereo MP3, stay within 8192. ASan cannot see it (the stub's buffers are one static array).
  The plan met this class for WAV and closed it there only (`phase-1-amisqueeze.md:346-348`).
- failure scenario: `AUDIO=PAULA` or `PAULA8` (or AHI missing, `player.c:481-488`), FLAC decoded on the Amiga, or
  `amisqueeze.fpu` with MP3; the server sends a mono track at 8-24 kHz (a 22.05 kHz mono MP3 podcast, a mono FLAC):
  the first block writes into the next channel's or block's buffer (garbage heard) and, for the last buffer, 8 KB
  past the `AllocMem` region (chip RAM of another program or the free list, unseen). The same when an MP3 stream
  turns mono at the start of a `run()` call.
- rule: A6; A2 (`output.c:180`, `player.h:409-411` promise the bound)
- proven or inferred: proven on the host; the corruption on the Amiga follows from `amiga_paula.c`'s layout (to
  confirm only by a run). Would be 100 if a server's usual path to a Paula player sends mono at 28.6 kHz or below.
- suggestion: the decoder returns 0 from the call that first sets its format (FLAC once open, MP3 at a format
  change), as the WAV parser does, so that `feed_audio` sizes from the real format; a clamp to
  `PAULA_BLOCK_SAMPLES * divisor` frames in `convert_paula` as a safety; a test with a decoded mono 22.05 kHz track.
