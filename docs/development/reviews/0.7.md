## 3. Findings at 75 or more

**R1. WAV header guards of 0.7 that no test sees removed; two stop a division by zero, one a loop without end**
(score 75)
- dimension: Tests / Code
- file / line: `src/amisqueeze/decoder.c:54`, `:56`, `:94` (and `:50`, `:77`, `:83`, `:90`, `:117`);
  `tests/test_core.c:1448-1497` (`test_wav_refused`)
- evidence: `if (bits % 8 != 0 || bits < 8 || bits > 32)` (`:54`), `if (channels < 1 || channels > 2)` (`:56`),
  `if (len > WAV_HEADER_MAX || off + 8 + len > WAV_HEADER_MAX)` (`:94`). `test_wav_refused` uses only 6 channels,
  12 bits and a 5000-byte LIST chunk, which trips both clauses of `:94` at once. Planted in throwaway worktrees:
  - `bits < 8`, `channels < 1` and the first clause of `:94` removed together: test_core green (1196 checks, 0
    failed; review-protocol-security); the second clause of `:94`, `n < 40` and the GUID check of `:50`,
    `bits > 32`, `0x7fffeffc` of `:90` removed: green too (review-tests-docs);
  - with rows bits 0 and channels 0 added to `test_wav_refused` and the guards removed: `decoder.c:174` (cited as
    `:175` by the agent) `n -= n % d->in_frame`: "runtime error: division by zero" under UBSan; on the audio
    output, the same at `stream.c:527` (`full -= full % frame`); with the guards, the same rows pass;
  - the first clause of `:94` removed and a chunk length of `0xFFFFFFF8`: `off + 8 + len` wraps to `off` and
    `wav_header()` never returns (killed by a 20 s `alarm()`); with it, "wav: header too long, track skipped".
  - read in the code, not run: without `:117` (`d->limited = 0`), a WAV with a size followed by a raw PCM track
    would leave that track counted against a spent `data_left` and drop it (`prepare_decoder`, `stream.c:355-365`,
    does not reset it); without the `complete` branches of `:77` and `:83`, a complete track under 12 bytes, or
    one ending between two chunks, would wait forever (the only "ends in its header" case, cut at 30 bytes, goes
    through `:102`).
- failure scenario: a later change to `wav_format` (another sample size, more channels) drops `bits < 8` or
  `channels < 1`; `make test` stays green; a server, or a file it relays, sends a WAV header with 0 bits or 0
  channels: a division by zero, a trap on the 68k. Or the first clause of `:94` goes: a header with a chunk length
  near 2^32 hangs the single task, Ctrl-C included.
- rule: `CONTRIBUTING.md:11` ("add tests for what you change in the portable core"), `CLAUDE.md` ("extend the tests
  with each step"); A4, A6. The same class as the 0.6 batch "guards no test sees removed".
- proven or inferred: proven (planted defects, UBSan, a timeout); the `:117` and `:77`/`:83` parts read only; the
  trap on the 68020 inferred.
- suggestion: rows in `test_wav_refused`: bits 0 and 40, channels 0, an extensible `fmt` of 18 bytes, a LIST
  length of `0xFFFFFFF8` (with a bounded run), two chunks over 4 KB together; a complete track under 12 bytes and
  one ending between chunks; a limited WAV followed by a raw PCM track.
- found by: review-protocol-security (75) and review-tests-docs (75), merged; each would drop it to 50 if guards
  that are right today but untested were judged acceptable.
- seen before: new (the code is new in 0.7).

## 5. The 50 list

New in 0.7:

- WAV rate wrap (proven): a WAV `fmt` with rate `0x40000000`, 16 bits, stereo makes `pcm_bytes_per_sec`
  (`stream.c:181`, `uint32_t`) 0; `wav_format` accepts it; the virtual output hands nothing over (0 bytes after
  62 s, RUNNING, elapsed 0); with AHI the rate goes to `plat_audio_send` unchecked. Only an absurd or hostile header
  reaches it; 75 if hostile servers are counted as normal input (A6). An upper bound on the rate would close it.
  `decoder.c:43` ("f set if amisqueeze can play it") is then not quite true.
- The `aac` row of the user guide (`:122`, "Music Assistant still shows the track as playing") was written in
  `97731fd`, before `18e9edc` made the refusal STMc+STMn; not shown tried again with Music Assistant. To confirm
  with the Music Assistant check by hand planned before the tag.
- `stream_flush`: the "nothing playing" branch (`stream.c:86-89`) can be removed with `make test` green (the
  LOADED case, autostart 0, untested); `stop_decoder` in it is caught only by an internal-state check
  (`test_core.c:2176`), not by the output; no fake-server scenario sends `strm f` or a refused stream.
- `architecture.md:32-33`, `:71-72`: the stream socket "readable while the ring has room", "no longer read" when
  full; since `READ_MIN_SPACE`, 8 KB free in BODY and 2 KB in HEADERS (internal).
- The new VERBOSE message `stream: WAV header: ...` is not among the events of the guide's catch-all row (`:511`).
- Stale statuses in the plan (internal): tools-4 "no versioned template" (`README.md:148`,
  `phase-0-tooling.md:51-55`; the template came in `7c01390`); tools-1 "Docker mode not tested yet"
  (`phase-0-tooling.md:13`; the CI uses it); player-7b 🔶 with nothing said to be left (`README.md:163`); "the next
  review is the one before 0.6" (`README.md:177`); `phase-3-release.md:179-181` "the tooling changes only when a
  review misses a real defect", while `.claude/` changed in the range by the user's decision (`CLAUDE.md` allows
  it).
- Not marked as agreed with the user: the refusal of a format moved to STMc+STMn with the request fix
  (`README.md:73-76`, from an open point "for the user to decide"); the CI actions pinned by SHA (`e5b87d3`);
  `tools/amiga/cpucount.c` and `make cpucount` (`2a92698`).
- `phase-1-amisqueeze.md:669` "(HostTest)", the name of a local player (internal).
- `tools/amiga/cpucount.c:17`: `(ds_Days*1440L + ds_Minute)*60L*50` overflows a signed 32-bit `long` in 2026
  (undefined; wraps in practice, the loop wrong once in about 994 days). Developer tool, never shipped.

## 6. Checked and found solid

  FLAC frame header 16, LAME header, ID3v2 skip, minimp3's frame clamped, WAV chunks 4 KB, `ring_peek` and

  takes space. The `strm s` field offsets match LMS 9.1's layout; `STAT` 53 bytes as LMS unpacks it.

  track is complete once later tracks fill the ring.
- Every clock difference wraps right as `uint32_t`; positions in `uint64_t`; every division guarded (with R1's
  guards in place).
- Platform: every exit label of `main()` releases exactly what was opened; AHI requests always collected
  (`CheckIO` + `WaitIO`, abort from the first one); reconnection resets audio; sockets closed on every failure;
  `ahi_prefs_unit`, `GetVar` and the ToolTypes line bounded.
- Safety nets red on plants: UBSan (signed overflow, an out-of-bounds store), check-saves on both builds,
  `check-version.py`, the readme check, `make dist` on a -dev version, the tag-name check of `release.yml`.
- CI: least-privilege tokens, actions pinned by SHA, image by digest, no token in the build container, no
  injectable `${{ }}` in `run:`.
- The CHANGELOG's Unreleased part covers every user-visible commit; links and anchors of README, CONTRIBUTING and
  the guide resolve; option and message tables complete for the Amiga build.
